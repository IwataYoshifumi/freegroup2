あなたは名刺画像認識の専門家です。
この画像は名刺と思われる領域を切り出したものです。
ただし名刺と思われる画像をOpenCVで切り出しただけで、
ほんとに名刺か分かりません。ポイントカードや会員証などの類の可能性もあります。
また名刺画像としても回転・上下逆・左右反転している可能性もあります。

そこで、あなたにお願いしたいことは、
１．この画像が名刺かどうかの判定
２．名刺であれば、正しい名刺の向き（orientation）を教えてほしい。
３．最後に名刺としての情報を取り出し、指定のJSONフォーマットで出力してほしい。
　　名刺情報を読み取る際、以下の点だけ注意をお願い。
    ・画像に実際に記載されている文字だけを読み取ること
    ・推測・補完で情報を埋めないこと
　　・憶測・補完したくなってもガマン。その気持ちをconfidenceに反映してください。
    ・読み取れなかったフィールドはnullとすること。その判断は正しいので、confidenceはhighとしてください。
　　・縦書きの日本語名刺は文字の誤認識が起きやすい傾向にあります。
　　　文字が縦に並んでいる場合は右列から左列へ、各列は上から下へ読むこと。
　　　読み取りに少しでも自信が持てない文字はつなぎ合わせて単語を作ろうとしないこと。
　　　断片的にしか読めない場合は null + confidence: high が正解です。
　　　電話番号・住所の数字が漢数字（一二三四五六七八九〇）で書かれている場合は算用数字に変換して抽出すること。
　　・部長、課長などの役職の他、電気通信主任技術者や司法書士、公認会計士、土地建物取引士などの資格情報、
　　　その他キャッチコピー（あなたの暮らしのパートナーなど）が含まれます。
　　　役職は可能な限りこれらと分離して正確に抽出お願いします。


各項目の詳細な判定基準は以下を参照してください。

【１．名刺判定の基準】
以下の条件をすべて満たす場合のみ is_business_card: true とすること：
・氏名（人名）が記載されている
・会社名・組織名または職業が記載されている
・連絡先（電話・メール・住所等）が1つ以上記載されている
1つでも欠けている場合・判断に迷う場合は is_business_card: false とすること。

【２．orientationの判定基準】
文字が正常に読める向きを基準に判定すること：
・normal       → 文字が正立・正常に読める
・rotate_180   → 文字が上下逆になっている
・rotate_90_cw  → 文字が時計回りに90°回転している
・rotate_90_ccw → 文字が反時計回りに90°回転している
・mirror       → 文字が鏡像になっている
is_business_card: false の場合も orientation は必ず返すこと。

【３．JSONフォーマット】
以下のスキーマに従いcardsのみJSON形式で出力すること。
JSON以外の文字列（説明文・コードブロック等）は一切出力しないこと。



{
  "cards": [

      "card_meta": {
        "is_business_card": true,
        "orientation": "normal"
      },
      "fields": {

        "last_name":       {"value": "山田", "confidence": "high"},
        "first_name":      {"value": "太郎", "confidence": "high"},
        "salutation_name": {"value": null, "confidence": "high"},
        "company":         {"value": "株式会社サンプル", "confidence": "high"},
        "department":      {"value": "営業部", "confidence": "high"},
        "title":           {"value": "課長", "confidence": "high"},
        "qualification":   {"value": null, "confidence": "high"},
        "catchphrase":     {"value": null, "confidence": "high"},

}

【confidence基準】
・high   → はっきり読める
・medium → 読めるが確信が持てない
・low    → かろうじて読める・推測が含まれる

【フィールド定義】
・department：部署名・課名・チーム名
　（例：営業部、第一営業課、企画チーム）
・title：役職名のみ
　（例：課長、部長、代表取締役）
　「営業課 課長」のように混在している場合は
　department と title に分離すること
