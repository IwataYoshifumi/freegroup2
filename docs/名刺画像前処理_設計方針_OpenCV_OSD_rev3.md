## 0. パイプライン全体と本書の範囲

名刺取り込みの前処理は次の流れ。

```
元画像（複数枚の名刺を含む。複数枚同時撮影が主用途）
  ↓ ① OpenCV 切り出し（名刺領域の検出）         ← 第1部で扱う
  ↓ ② 透視変換（四隅から正対画像へ）             ← 射程外（既存処理）
  ↓ ③ Tesseract OSD 向き補正（0/90/180/270）     ← 第2部で扱う
  ↓ ④ Claude OCR（文字読み取り＋構造化 JSON）    ← 射程外（OCR 正本）。条件付き2回OCRを存置
```

③ の OSD が ④ の前段で画像を正立させる。ただし OSD は文字量不足等で失敗するケースが残るため（§2.3）、④ 側の条件付き2回OCR（Claude が回転を検知したら回転補正して2回目）は存置する（§2.2.2）。**rev2 で「1回OCR化」とした方針は、第1段の検証で OSD が全部の向きを救いきれないことが実機確認できたため、rev3 で差し戻す**（改訂履歴・§2.2.2・§4.1）。

本書が扱うのは ① 切り出し と ③ 向き補正。② 透視変換と ④ OCR 本体は扱わない（④ は OCR 正本 統合版 v1.6.1 が扱う）。

両者に共通する撮影マニュアルと評価基準は第3部に1つにまとめる。実装着手の前に「評価基準の設計」を済ませる方針は全体に適用する。

# 第1部 OpenCV 切り出し改善

## 1.1 現状の問題（OR 合成）

現行の切り出しは、複数のマスクを OR 合成し、クロージング後の1枚から輪郭を取って候補を抽出していた。弊害が2つ。

**(1) 背景によって効くマスクが入れ替わる。** 暗い机では輝度差マスクが各名刺を塊として拾い彩度マスクは死ぬ。緑の机では彩度マスクが各名刺を別矩形として拾い、輝度差・エッジは背景ノイズで使いにくい。背景しだいでどれか1枚は必ず死ぬ。

**(2) OR 合成が良い切り出しを台無しにする（全廃する）。** OR 合成は3マスクを混ぜてから領域を取るため、効いていないマスクのノイズや隣接名刺をつなげた塊も拾う。3枚が1枠に統合される事故はこれが原因。3背景のマスク実地確認では、効くマスクが名刺を丸ごと拾い、効かないマスクは真っ黒かノイズで、マスクをまたいだ部分分担は観測されなかった。**OR 合成は本用途でデメリットのみのため全廃する**（将来の例外救済は 1.3.4 に残置）。

## 1.2 新設計の柱

「マスクを混ぜてから判断」をやめ「各マスクで候補を出してから名刺らしさで選別」に変える。処理の流れ（データの流れ順）：

1. **各マスクで候補を出す**（OR 合成しない）。各マスクごとにクロージング → findContours → convexHull → minAreaRect まで回し、中心座標・幅・高さ・回転角を持つ候補を得る。
2. **名刺らしい縦横比の候補だけ残す**（採否の基準）。縦横比は minAreaRect の短辺・長辺から算出し、名刺らしい範囲に収まるものを採用する。大きさは採否の主基準にしない（1.2.4）。
3. **1マスクでしか出なくても比が範囲内なら採用して DB 化**。票数は採否に使わない。各候補が比を満たすかだけで採否が決まる（1枚撮り・候補1個でも成立）。
4. **マスク横断・通常／反転横断で重複をまとめる**。中心座標が近いもの（＋矩形の重なり割合 IoU）を「同じ名刺」とみなし1件に統合する。採否でなく重複除去の工程。

### 1.2.1 各工程で使う OpenCV 関数

findContours（マスクの白い塊の輪郭を点列で取る）→ **convexHull（凸包で輪郭の凹凸を均す）** → minAreaRect（傾きを許した最小長方形。中心・幅・高さ・回転角・短辺長辺比が出る）→ boxPoints（四隅に展開。透視変換に渡す）。順序は findContours → convexHull → minAreaRect → boxPoints。

**convexHull を挟むのは rev2 から追加された処理**（rev2 §1.2.1 は findContours → minAreaRect 直結だった）。輪郭の凹凸を均してから外接矩形を取ることで比を安定化させる。実コードは `hull = convexHull(cnt); rect = minAreaRect(hull)` で結線済み。

実装注意：boxPoints の4点順序は一定でないため、透視変換前に四隅を一定順序（左上→右上→右下→左下）へ並べ替える（実コードは TL→TR→BR→BL 整列済み・付録参照）。

### 1.2.2 縦横比は minAreaRect で測る

外接矩形（boundingRect）は水平垂直に沿った長方形しか返さず、斜め名刺で比が崩れ正当な名刺を弾く。minAreaRect は傾きごと囲むので斜めでも本来の比が出る。

### 1.2.3 縦横比のしきい値（下限 1.52・上限 1.8）

**rev2 の「1.6〜1.8 に確定」から、下限を 1.52 に拡張した**（上限 1.8 は据え置き）。判定は `1.52 ≤ aspect ≤ 1.8`。

- 拡張の経緯：白い名刺が反転 adaptive 経路で比 1.53 前後に出るのを救済するため、たんたんが実測（1.55／1.53／1.50 の3点比較・検出率と誤検出の増減を確認）に基づき確定した。日本標準名刺 91×55mm（≈1.65）・欧米標準 89×51mm（≈1.75）を含みつつ、白名刺救済の余地を足した値。
- 比は名刺という物の形そのもので、解像度・撮影枚数によらないため、画像によらない固定範囲で採否の主基準に使える。ただし「比は不変」は真上撮影が前提。透視ひずみが強い斜め撮影では minAreaRect で測っても比が台形化してずれ、範囲外に出て弾かれうる。**斜め耐性は比フィルタでなく撮影マニュアル（真上から撮る・第3部）で担保する**。

### 1.2.4 サイズは採否の主基準にしない（緩い絶対下限のみ）

採否は縦横比で行い、サイズを採否の主基準にしない。大きさを主基準にすると、候補が1個ないし極少数のとき基準が立たず、名刺1枚撮りで破綻する。

サイズに残す役割は **OCR 不能な極小候補を落とす緩い絶対下限**のみ（実コードの既定 `_DEFAULT_MIN_CARD_AREA_PX = 8000`）。

### 1.2.5 残す既存処理・反転リトライの常時化

- **クロージング（穴埋め）は各マスクに残す**（同一マスク内で割れた塊をつなぎ直す。実コードは iterations=2）。OR 合成はやめるがクロージングはやめない。
- **反転リトライは無条件で常時実行する。** rev2 は「残す」とのみ記載で条件を明示していなかったが、実コードは旧「passed==0 のとき」ゲートを撤廃し、通常の成否に関わらず常に反転リトライを実行する。さらに次の2点が rev2 未記載の実装として加わっている：
  - **通常／反転の attempt 横断統合**：通常（normal）と反転（inverted）の両方で候補を出し、横断して重複統合する。統合時は origin="normal" を優先する。
  - **反転側の polygon 外側拡張**：反転経路の候補は polygon を外側へ拡張してから扱う（白名刺の縁の取りこぼし対策）。

### 1.2.6 マスクは4種（adaptive を含む）

rev2 は3種（輝度差 diff・エッジ edge・彩度 sat）前提だったが、**実コードは4種**：diff／edge／sat／**adaptive**。

- adaptive は局所二値化（cv2.adaptiveThreshold）で、低コントラスト背景上の白名刺の縁を救済する4本目として追加された。
- sat（彩度）マスクは、白い名刺×明るい机のような極低彩度の場面では実質死ぬ（候補ゼロ）。その穴を diff／edge／adaptive で受ける構図。

## 1.3 効くケース／危ういケース

### 1.3.1 素直に効くケース
複数名刺が間隔をあけて並び背景とコントラストがある。各マスクが各名刺を別塊で出し、比で通り、中心座標で統合される。OR 合成の地続き事故が消えるため現行より明確に良くなる。**第1段の検証でも、間隔をあけた名刺は安定して切り出せている。**

### 1.3.2 危ういケースと対処

| # | ケース | 起きること | 対処 |
|---|---|---|---|
| 1 | 隣接・接触している名刺 | 2枚を1塊として検出、比が崩れ両方弾かれる | 現フェーズでは対応対象外。**撮影マニュアルで回避（名刺を離す・必須）**。将来 watershed / distance transform / 凹点分割等の余地は閉じない |
| 2 | 割れた名刺（白帯・ロゴで分裂） | 小さすぎる候補が2つ出て弾かれる | クロージングで塊をつなぐ（1.2.5）。繋ぐのは同一マスク内の分裂のみ |
| 3 | 同じ名刺を複数マスクがずれて出す／隣を誤統合 | しきい値が緩いと別名刺を融合 | 中心距離＋IoU の AND 併用（1.4）。しきい値は評価基準で詰める |
| 4 | 1マスクだけが出した候補の信頼性 | 木目・影が比に合致しゴーストとして通る | 誤検出率を評価基準で測る。抑制指標（長方形度・凸包率＝充填率）の追加は将来設計（§4.2） |
| 5 | 回転・斜めの名刺 | 真上前提なら比は崩れないが、透視ひずみが強いと比がずれ範囲外に出うる | 採否は比で行う。斜め耐性は撮影マニュアルで担保 |
| 6 | 全マスクが死ぬ背景 | 候補ゼロ／白黒反転状態 | 反転リトライが受け持つ（1.2.5・常時化） |
| 7 | **白名刺×明るい机の低コントラスト（新規・検証で確定）** | 候補は出るが、左右の境界がにじみ外接矩形が横に膨張、比が 1.20〜1.33 に潰れて aspect_invalid 却下。検出されず消える | 比のしきい値では救えない（1.33 は現行下限 1.52 から遠く、下げると正方形ゴーストを大量に拾う）。**撮影マニュアルで回避（背景無地・白名刺は暗色下敷き・必須）**。充填率／凸包フィルタによるシステム救済は将来設計（§4.2） |

#### 1.3.2.1 ケース7（白名刺取りこぼし）の検証実測

第1段の検証画像④（4枚簡単）で、左下の白い名刺1枚だけが検出されなかった。既存中間データ（debug_json）の数値で原因を切り分けた結果：

- 太田領域に候補を出したマスクは3つ（diff／edge／adaptive）。いずれも単一の塊で、面積は採用カード並み（398k〜466k vs 採用 412k〜459k）。痩せ・分裂ではない。
- 違いは**充填率（blob面積／minAreaRect面積）が 0.69〜0.79**（採用カードは ≈1.0）と、**横方向に実カード幅 +130〜190px の膨張**。これが比を 1.20〜1.33 に潰している。
- 縦寸は実カード相当を正しく捉えている。塊は名刺全体を捉えているが、外接矩形だけが不定形に膨らんでいる＝低コントラスト境界のにじみが主因。
- sat マスクは極低彩度（sat_white_ratio=0.021）で太田領域に候補ゼロ＝実質死。
- 結論：原因は「白名刺×明るい机の低コントラスト境界で塊が横ににじみ、外接矩形が膨張して比が潰れた」。しきい値緩和では救えず、救うなら充填率／凸包の新フィルタ（誤検出率評価とセット）が必要。本フェーズでは撮影マニュアルでカバーする。

### 1.3.3 効く範囲のまとめ
確実に良くなるのは「離れて置かれ背景と差のある名刺」。(1) 接触・(7) 白名刺低コントラストは撮影マニュアルで回避、(2) はクロージング、(3)(4) は評価基準で詰める。

### 1.3.4 OR 合成の将来的な例外救済（残置）
全廃するが、将来「どの単一マスクでも名刺を丸ごと拾えず複数マスクの部分を足さないと名刺にならない」画像が評価で出た場合に限り、OR 合成を局所救済策として再検討する余地は残す。現時点では実装しない。

## 1.4 重複統合の判定（現状確定値）

同じ名刺を複数マスク・通常／反転が少しずつ違う座標で出したときの統合は、次で行う（実コード現行値）：

- **判定：IoU ≥ 0.30 かつ 中心距離 ≤ 0.50×対角線（AND 併用）。** 既定 `_DEFAULT_DEDUP_IOU_THRESHOLD = 0.30` / `_DEFAULT_DEDUP_CENTER_DIST_RATIO = 0.50`（settings で上書き可）。AND 併用は過統合（別名刺の誤融合）を避ける保守側の判定。マスク横断統合と通常／反転横断統合の両方で同じ判定関数を使う。
- **採用座標：暫定で面積最大を採用**（面積降順に走査）。rev2 §1.4 で「面積最大／平均／比最近のどれか未確定」としていた論点は、実コードでは面積最大の暫定実装。確定は評価基準（3.2）で「正解の切り出し（正解4点）」を定義するのと一体で詰める。

# 第2部 向き判定対策（Tesseract OSD ＋ 条件付き2回OCR）

## 2.1 現状の問題（Claude は幾何的向きを知覚できない）

名刺が回転した状態で表示・保存され、回転画像を誤読する。しかも confidence=high でサイレントに DB へ入るため信頼度フィルタで弾けない。

真因（確定）：**Claude（Sonnet 4.6）は画像の幾何的な向きを知覚できない**。同一画像を4方向に回して向き判定させると4枚中3枚を normal と返す。テキストは回転していても読めるため「読める＝正立」と取り違える。プロンプト調整は2回試して両方失敗し打ち切り済み。

OSD 置換でこの問題は**大幅に低減するが、完全には消えない**。OSD が失敗して normal フォールバックした画像（§2.3 の細帯型）は回転したまま残る。第1段の検証でも、OSD 失敗カードのうち本物の名刺は倒れたまま通った（§2.5.1）。

## 2.2 新方針

1. **向き判定を Claude → Tesseract OSD に置き換える。** `pytesseract.image_to_osd()` で 0/90/180/270 度を決定的に取得する。
2. **OSD 失敗時は normal フォールバック**（倒す方向に賭けない）。
3. **補正画像は非破壊保存（別パス）**にし、元クロップを残す。
4. **向き判定の指示はプロンプトから外さず、役割を変える。** OSD が前段で向き補正を担うため、プロンプトの向き指示は (a) 報告のみ、(b) その報告で処理を分岐させない、(c) OSD との突き合わせ用、に作り替える。指示文は残すが文面は書き換える（具体文面は未確定・§4.2）。ローマ字アンカー版は採らない。

### 2.2.1 検証済みの事実
- 横カードの 90° 回転：4/4 正しく判定。
- 縦書き正立名刺：rotate 0＝無回転と判定。縦書きを倒す逆事故は起きなかった。
- `script`（言語）判定はデタラメ → **向き（orientation）だけ使う**。第1段の検証でも日本語名刺に Cyrillic/Arabic 等が付いたが、向き補正は正しく効いた。
- **confidence 値は採否に使えない**（低 confidence でも正解のことがある）。第1段の検証で、conf 0.94 等の低い値でも正しく正立補正できたカードが複数あった。confidence で分岐しない。

### 2.2.2 条件付き2回OCR は存置する（rev2 の1回OCR化を差し戻し）

rev2 は「OSD が前段で正立させるので Claude は1回読むだけでよい」として条件付き2回OCR の廃止・1回OCR化を打ち出した。**rev3 でこれを差し戻し、条件付き2回OCR を存置する。**

- 差し戻しの理由：第1段の検証で **OSD は全部の向きを救いきれない**ことが実機確認された（§2.3・細帯型などで OSD 失敗 → 倒れたまま通る）。OSD 一本に賭けると、OSD が失敗した倒れカードを救う経路がなくなる。OCR（Claude）が回転を検知したら回転補正して2回目をかける従来の保険を残し、OSD 失敗の取りこぼしを2段目で拾えるようにする。
- これは「OSD 失敗を Claude で救おうとしない」という rev2 の判断の見直しでもある。rev2 は「Claude も倒れた画像を normal に倒す偏りがあるため保険にならない」としたが、第1段の検証では OSD 失敗の本物名刺5件すべてが OCR で business_card として読めた（§2.5.1）。Claude OCR は倒れたままでも中身を抽出できる実績が出たため、2回目OCR を保険として残す価値がある。
- `raw_json_2` フィールドは引き続き残す（2回目OCR の受け皿）。

### 2.2.3 mirror 補正は引き継がない（既知の限界）

OSD は 0/90/180/270 度の回転のみを返し、鏡像は判定できない。旧仕様でも mirror は精度保証のないオマケ扱いだった。OSD 置換に伴い mirror 補正は引き継がない（既知の限界）。実害は小さい（現実の名刺取り込みで鏡像はまず発生しない）。

## 2.3 OSD の弱点・失敗の定義・負荷・ライセンス

**弱点と切り分け：** 検証で失敗するのは文字量不足のケース。細帯クロップ（90° 回転＋細い帯状の切り出し）は OSD の真の限界 → normal フォールバックで受ける。切り出し失敗による塊（3枚が1枠等）は OSD 以前の問題で第1部の領分。

**OSD 失敗の定義：** `image_to_osd` が例外を投げたケースを「失敗」とみなし normal フォールバックする。confidence 値は失敗判定に使わない。ハング対策に timeout を設ける。

**失敗メッセージは複数種ある（検証で確定）：** 第1段の検証で観測された OSD 失敗は2種。
- `Too few characters. Skipping this page` ＝文字量不足（多数派）。
- `Invalid resolution 0 dpi. Estimating resolution as N` ＝クロップ画像に DPI 情報がなく Tesseract が警告（少数）。たいてい無害（推定 dpi にフォールバック）。
- **実装は特定文字列で決め打ちせず、`image_to_osd` の例外（error キーの有無）で失敗判定する。** これにより timeout 等の別理由も拾える（実装済み・osd_debug_badge も error キー参照）。

**負荷：** OSD（--psm 0）は向きと文字種だけを返す軽い処理で、1枚あたりコンマ数秒〜数秒。バックグラウンド処理の中で1枚ずつ走るため利用者を待たせない。

**ライセンス：** Tesseract は Apache License 2.0（商用利用・改変・再配布可）。FG2 の Source Available／商用ライセンス／ディストリビュータ制度と両立する。配布時はライセンス文・著作権表示の同梱、依存ライブラリ・言語データ（osd.traineddata 等）のライセンス確認をすること。

**配置：** Tesseract 本体＋osd.traineddata はサーバー1台に入れれば足り、利用者の PC には不要。パスは設定から解決する。

## 2.4 EXIF との関係（二重補正は起きない）

OCR 正本 統合版 v1.6.1 §7.2 で確認：EXIF の取得はアップロード受信直後の生バイト列の時点で行い、exif_transpose で正立補正したあとは EXIF が失われる。exif_json は GPS 等を別途記録するだけで向き補正には使わない。したがって OSD 補正と EXIF 補正が二重がけになる経路は存在しない。EXIF Orientation（物理回転）と BusinessCard.orientation（名刺の向き5値）は別物で混同しない。

実装着手時、切り出し後カード画像が OSD へ渡る直前で EXIF 由来の回転が残っていないかを実画像1枚で最終確認する（§4.2）。

## 2.5 VLM が向きを吸収する可能性（論点を閉じる）

rev2 §2.5 では「OCR 本体が Claude なら天地が逆でも読めることが多く、OSD 自体が不要では」という指摘を保留論点としていた。**第1段の検証で答えが出たため、rev3 でこの論点を閉じる。**

結論：**OSD（向き補正）は必要。** ただし理由は「OCR が読めるようにするため」ではなく「**正立で表示・保存するため**」。

### 2.5.1 検証で確定したこと

- OSD 失敗カード8件のうち、本物の名刺だった5件は、正立補正なし（倒れたまま）でも Claude OCR が全件 business_card として読み、必要情報も取れた（has_minimum_info=yes）。残り3件は名刺でないゴーストで、Claude も正しく not_business_card と返した。
- つまり「倒れていても中身の抽出は OCR が救える」。一方で「表示・保存は倒れたまま残る」実害は消えない。
- したがって OSD は中身抽出のためでなく、正立表示・正立保存のために要る。VLM が向きを吸収するから OSD 不要、という方向には倒さない。

### 2.5.2 OSD 独立評価の実測（rev2 §3.2 の3指標）

第1段の検証で、リリースクリティカルの3指標を実物で握った（数値の網羅でなく実機での確認）：

- **(a) 補正成功**：rotate≠0 で補正したカード群（横 90°/270° 多数、上下逆 180°）は、補正後すべて OCR が business_card として読めた。誤った方向に回して読めなくなったカードはゼロ。
- **(b) 逆事故**：正立画像を誤って回したケースはゼロ（rev2 の「現状ゼロを下回らない」を維持）。
- **(c) 残存**：OSD 失敗で倒れたまま通った本物名刺は5件。ただし中身抽出は成功しており、残る実害は「表示・保存の傾き」のみ。これは撮影マニュアルの向き必須化（第3部）で入力側から消せる。

# 第3部 共通（撮影マニュアル・評価基準）

## 3.1 撮影マニュアル（複数枚を並べて撮影）

FreeGroup2 の名刺取り込みは、複数枚の名刺を机に並べて一度に撮影し、OpenCV が各名刺を切り出すことを主用途とする（これが OpenCV 切り出しの存在理由）。本マニュアルは、その複数枚同時撮影を成立させるための入力側の条件であり、評価基準（3.2）の入力前提を兼ねる。検証画像セットはこれに準拠して揃える。

利用者は事務作業の片手間で撮影することを前提に、必須は守られやすい最小限に絞り、それ以外は推奨とする。

**必須**

- 名刺を重ねない・離して置く
- 全部の向きをそろえ、文字が読める向きで置く
- 真上から撮る
- 背景は無地。白い名刺は暗色の下敷きの上に

**推奨**

- 影を出さない・明るさを均一に

各必須項目が対処するケース（裏返し）：重ねない＝接触名刺で2枚消える（#1）／向きをそろえる＝OSD 失敗時の倒れ残存（§2.5.2 c）／真上から＝透視ひずみで比が台形化（#5）／背景無地・白名刺は暗色下敷き＝低コントラストで外接矩形が膨張し取りこぼす（#7）。

## 3.2 評価基準（実装より先に設計する）

切り出し・向き判定とも「直したつもりが別を壊す」反復を避けるため、実装より先に評価基準を作る。定める項目：

- **正解4点**：各名刺の正解の切り出し座標（四隅）。
- **正解の名刺集合（枚数）**：各検証画像に名刺が何枚あるか。検出率の分母。検証画像⑥は実物8枚（rev2 本文の「6枚」は誤記。実コード／テストは8枚で確定済み）。
- **検出候補と正解の対応づけ規則**：マッチとみなす IoU しきい値。
- 上記を土台に、改善前後で検出率・誤検出率を測る。
- 第1部の危ういケース（離して並べた／くっつけた／白帯／斜め／全マスク弱／**白名刺低コントラスト#7**）と、第2部の向き（横 90°・縦書き正立・細帯）を、それぞれ用意して測る。

縦横比のしきい値（下限 1.52・上限 1.8）は確定済みのため測る対象に含めない。詰める対象は、統合の IoU しきい値・採用座標の決め方・OCR 不能を落とす緩い絶対下限の値・**白名刺救済の充填率／凸包フィルタを入れるか（誤検出率とのトレードオフ）**など。

**OSD の独立評価：** §2.5.2 の3指標（補正成功率・逆事故率・残存率）。第1段で実物確認済み。新規導入後は横・縦・細帯の各ケースで回帰確認する。

# 第4部 確定事項と未確定事項

## 4.1 確定

**切り出し（第1部）**
- OR 合成を全廃し、各マスクで findContours → convexHull → minAreaRect まで回して座標付き候補を出す。
- 採否は縦横比（下限 1.52・上限 1.8、画像によらない固定範囲）で行う。
- サイズは採否の主基準にしない。OCR 不能な極小を落とす緩い絶対下限のみ（既定 8000px）。
- 1マスクでも比が範囲内なら採用（票数ルールなし・1枚撮りでも成立）。
- マスクは4種（diff／edge／sat／adaptive）。adaptive は白名刺低コントラスト救済の4本目。
- 反転リトライは無条件常時化。通常／反転を attempt 横断統合（normal 優先）、反転 polygon は外側拡張。
- 重複統合は IoU ≥ 0.30 かつ 中心距離 ≤ 0.50×対角線（AND 併用）。採用座標は暫定で面積最大。
- 斜め耐性・接触回避・白名刺低コントラスト回避は撮影マニュアルで担保。クロージング存置。
- 接触名刺・白名刺低コントラスト（#7）は現フェーズ対象外（将来の救済余地は閉じない）。

**向き判定（第2部）**
- 真因は「Claude は幾何的向きを知覚できない」。プロンプト調整は打ち切り。
- 向き判定を Claude → Tesseract OSD に置換。orientation のみ使う（script は使わない）。confidence で分岐しない。
- OSD 失敗（image_to_osd の例外）時は normal フォールバック。timeout を設ける。失敗判定は特定文字列でなく例外（error キー）で行う。
- 補正画像は非破壊保存（別パス）、元クロップを残す。
- **条件付き2回OCR を存置する**（rev2 の1回OCR化を差し戻し。OSD が全部の向きを救えないため。§2.2.2）。`raw_json_2` は2回目OCR の受け皿として残す。
- mirror 補正は引き継がない（既知の限界）。
- 向き判定の指示はプロンプトに残し、役割を「報告のみ・採否に使わない・突き合わせ用」に変える。文面は未確定。
- EXIF 二重補正は起きない。実装時に実画像1枚でコード挙動を最終確認。
- Tesseract は Apache 2.0。サーバー1台配置・利用者 PC には不要・負荷軽。

**検証で確定（第1段）**
- OSD は効いている（補正成功・逆事故ゼロ）。残存（OSD 失敗の倒れ）も中身抽出は OCR が救い、実害は表示・保存の傾きのみ＝撮影の向き必須化で消す。
- 主用途は複数枚同時撮影。撮影マニュアルの必須は4項目（重ねない・向きそろえ・真上・背景無地）。
- 白名刺取りこぼし（#7）は低コントラストで外接矩形が膨張し比が潰れる現象。しきい値では救えず、充填率／凸包フィルタは将来設計。本フェーズは撮影マニュアルでカバー。

**デバッグ表示・保存（第1段で実装済み）**
- 名刺一覧・詳細画面に OSD 向き判定（rotate / conf / OSD失敗＋理由）を DEBUG 時のみ表示。
- tesseract_ocr の text/data は DEBUG 時のみ保存。本番は lang のみ（フル OCR 呼び出し自体を省略）。OSD ブロック（rotate/conf/script）とは別系統で無影響。

## 4.2 未確定（評価基準の後で詰める／たんたんの判断・確認待ち）

## 付録：実装着手時の注意（設計判断ではない備忘）

- **boxPoints の4点順序**：透視変換前に四隅を一定順序（左上→右上→右下→左下）へ並べ替える（実コード整列済み）。
- **minAreaRect の角度規約**：OpenCV バージョンで変わる。短辺・長辺から比を出す分には影響しない。
- **OSD の rotate 値 → 補正回転**：image_to_osd の rotate 値（0/90/180/270）を Pillow の回転にマップして非破壊保存する。Tesseract の rotate は反時計回り基準。
- **OSD の例外捕捉**：image_to_osd を try/except で包み、例外時は無回転（normal）にフォールバック。timeout も設定。
- **convexHull**：findContours の輪郭をそのまま minAreaRect に渡さず、convexHull で凹凸を均してから渡す（比の安定化）。
