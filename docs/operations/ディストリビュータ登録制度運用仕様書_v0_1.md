## 第1章 本仕様書の位置づけ

### 1.1 目的と用途

本仕様書は、FreeGroup2 のディストリビュータ（登録事業者）登録制度の**運用手続きの詳細**を定める。LICENSE.md 第5条が定める登録制度の骨子を、実務として運用するためのルールに具体化する。

想定する主な用途は次の4つである。

1. **登録フォーム・退会フォーム実装の基準ドキュメント**：v2.freegroup.work 上に実装する各フォームの入力項目・バリデーション・公開判断ロジックの仕様根拠。
2. **ディストリビュータ募集開始時の運用ルールの明文化**：申請受付から審査・承認・通知までの手順の確定。
3. **審査運用プロンプト設計の元データ**：Claude Desktop で申請審査を補助する際のプロンプト設計のベースとなる確定情報。
4. **LICENSE.md 改訂・プライバシーポリシー追記の前提資料**：本書で確定した運用のうち、LICENSE.md・プライバシーポリシーへ反映すべき事項の管理（第10章）。

**本書は内部運用文書である。** 公開ドキュメントサイト（docs.freegroup.work）には掲載しない。一般向けの「登録のご案内」ページが必要になった場合は、本書から要約を抽出した別ページとして切り出す（別作業）。

### 1.2 正本順位

本制度に関する記述が複数ドキュメントで食い違った場合、次の優先順位で判断する。

| 優先 | ドキュメント | 役割 |
|---|---|---|
| 1 | `LICENSE.md`（v1.0.1）第5条・第6条・第4.2条・第1条 | 制度の**正本**（Single Source of Truth）。法的効力を持つ。 |
| 2 | 本仕様書 | 上記の**運用詳細**。LICENSE と矛盾する場合は LICENSE が優先。 |

本書は LICENSE.md の運用詳細であり、LICENSE.md の条文を上書き・変更するものではない。本書で新たに定めた運用のうち LICENSE.md に未反映のもの（書類確認・退会フロー・虚偽申告時の取消等）は、**第10章「反映待ち事項」で管理**し、LICENSE 改訂時に正本へ反映する。

### 1.3 用語の定義

本書で用いる主要用語は **別表1「用語集」** に定義する。各用語は可能な限り LICENSE.md の条番号と紐付けて定義しており、本書内で定義がぶれないようにしている。

CLA（コントリビューター・ライセンス契約）との関係：FreeGroup2 への貢献（プルリクエスト提出）は、**登録事業者（ディストリビュータ）またはその所属者に限られる**。登録事業者は、別途 CLA に署名することでコントリビューションが可能となる（詳細は `CLA-individual.md`（ICLA）・`CLA-corporate.md`（CCLA）を参照）。本書は CLA の内容には立ち入らず、一方向の参照のみを行う。

## 第3章 新規登録フロー

（根拠：LICENSE.md 第5.1条・第5.2条・第6条）

### 3.1 入力項目

登録フォームの入力項目は全23項目で、3つのグループに分かれる。各項目の完全な属性（null可否・公開条件・入力形式）は **別表2「登録入力項目一覧」** に定義する。本節はグループの趣旨を述べる。

- **グループ1：登録必須（項目1〜13）** — 事業者の同定、社員数・上場区分・保有ID数（LICENSE 第6条の登録料算定の基礎）、商用利用トリガー区分（第4.2条）、利用形態の概要。全項目必須（ただし項目8インボイス番号は任意・null可）。
- **グループ2：公開判断（項目14〜18）** — 公開・非公開の選択（必須・初期値なし）と、公開時のみ任意で入力する公開情報（ロゴ・業種・一言コメント・URL）。3.2 の公開判断ロジックに従う。
- **グループ3：初回登録時アンケート（項目19〜23）** — 全項目任意。マーケティング・製品改善の参考情報。

### 3.2 公開判断ロジック

（根拠：LICENSE.md 第5.2条）

- 公開・非公開は**二択**（公開 / 非公開）。
- **初期状態**：ラジオボタン2つはどちらも未選択（初期値を設定しない＝第5.2条第2項）。項目15〜18は非表示。
- 「**公開**」を選択 → 項目15〜18（ロゴ・業種・一言コメント・事業者ウェブサイトURL）が**条件付きで表示**される。
- 「**非公開**」を選択 → 項目15〜18は非表示のまま。当該登録は完全に非公開として扱われる（第5.2条第5項）。
- **入力した項目だけが公開される**（ロゴを登録すればロゴも公開、未入力の項目は公開されない）。
- 公開時、**事業者名（項目1）は必須**、ロゴ・業種・一言コメント等は任意（第5.2条第4項）。
- 公開・非公開の別はいつでも変更可能（第5.2条第3項）。公開・非公開によって登録料に差を設けない（第5.2条第6項）。

### 3.3 自動チェック（インボイス番号・国税庁照合）

> ※ 本節の運用は LICENSE.md に**未反映**（第10章で管理）。

- **インボイス番号がある場合（項目8が非null）**：国税庁の「適格請求書発行事業者公表サイト」で自動照合し、申告された事業者名・所在地と公表情報が一致するかを確認する。照合は審査ステップ（3.4）で Claude Desktop が担う。
- **インボイス番号がnullの場合**：自己申告のみで受け付ける。追加の自動照合は行わない。

### 3.4 審査フロー

> ※ 審査による承認・却下・追加書類請求の運用は、書類確認（第7章）とあわせて LICENSE.md に**未反映**（第10章で管理）。

審査は **Gmail 起点 + Claude Desktop 活用** で行う。登録数が少ない初期段階（フェーズ1）は手動運用とし、登録数の増加で運用が辛くなった段階でシステム化（フェーズ2）を検討する。

#### フェーズ1：手動運用（初期）

| ステップ | 内容 |
|---|---|
| ステップ1：申請受付 | v2.freegroup.work のフォームから申請。メール経路は `info-t@freegroup.work` → `iwata@network-tokai.jp` → `network.tokai.iwata@gmail.com`（既存お問い合わせフォームと同経路）。たんたんが受信。 |
| ステップ2：Claude Desktop でチェック | Gmail MCP 経由で申請メールを読み込み、(a) インボイス番号の国税庁公表サイト照合（web_search / web_fetch 使用）、(b) 申告内容の整合性チェック、(c) 不審点の抽出、(d) 推奨判断を依頼する。 |
| ステップ3：たんたん最終判断 | Claude Desktop の結果を踏まえ、**承認 / 追加書類請求 / 却下**を決定。連絡メールを送信（下書きは Claude Desktop で作成可）。 |
| ステップ4：登録完了通知 or 追加対応 | 承認時は登録完了通知（登録番号を記載）。追加書類請求時はその案内。 |

**審査ログ**：Gmail スレッドがそのまま履歴になる。専用の審査管理システムは設けない。

#### フェーズ2：将来のシステム化

- 登録数が増えて手動運用が辛くなったタイミングで判断する。
- フェーズ1の運用ログ（Gmail スレッド）が、システム化時のプロンプト設計・要件定義の元データになる。
- Claude Desktop 用の審査プロンプトはディストリビュータ募集開始後に具体化する（現時点では確定不要）。

### 3.5 承認・登録完了通知

- 承認後、登録事業者となる（LICENSE 第5.1条）。登録料（初期登録料・年間登録料）は LICENSE 第6条および附則A/Bのタリフ表に従う（料金の正本は LICENSE 側）。
- 登録完了通知メールには**登録番号**を記載する。登録番号は年次更新・退会申請時の照合キーとなる（第4章・第5章）。

## 第4章 年次更新フロー

（根拠：LICENSE.md 第5.3条・第5.4条）

### 4.1 更新タイミング

- 登録の有効期間は登録日（または更新日）から**1年間**（第5.3条）。
- 有効期間の満了までに更新することで商用利用を継続できる（第5.4条）。更新時には、その時点の社員数区分・総保有ID数に基づき登録料を再算定する（第5.4条・第6条）。

### 4.2 同フォーム流用・前年値デフォルト

- 更新は新規登録と**同じフォームを流用**する。
- グループ1（必須）・グループ2（公開判断）の各項目は**前年の登録値をデフォルト表示**し、変更があった箇所のみ修正する運用とする。
- 総保有ID数（項目11）・社員数区分（項目9）など料金算定に関わる項目は、更新時点の実績で必ず見直す。

### 4.3 更新時アンケート

- 更新時アンケートは**毎年内容を変更できる設計**とする（運用側でアンケート定義を書き換え可能な仕組み）。
- 初年度更新時アンケートの例（仮・確定ではない）：
  - 1年使ってみての満足度
  - 実際に活用できた機能
  - 使えなかった／不足を感じた機能
  - 事業展開の進捗
  - 開発元への要望

## 第5章 退会フロー

> ※ **本章の運用は LICENSE.md に未反映（反映待ち）。** 退会手続き・退会後の権利の扱いは第10章で管理し、LICENSE 改訂時に正本へ反映する。

### 5.1 退会パターン

退会理由は4区分とする。詳細は **別表4「退会パターン一覧」** を参照。

| 区分 | 名称 | 概要 |
|---|---|---|
| A | OSS層に戻る | 商用利用をやめる（自社利用＝OSS層として利用継続） |
| B | 利用終了 | FreeGroup2 の利用を完全に終了する |
| C | 廃業・解散 | 事業者自体の消滅 |
| D | その他 | 上記以外（別途判断） |

### 5.2 退会申請フォーム

- **窓口**：v2.freegroup.work 上の専用フォーム。
- **URL（予定）**：`v2.freegroup.work/distributor-withdrawal/`
- **入力項目**：

| 項目 | 必須/任意 | 備考 |
|---|---|---|
| 登録時のメールアドレス | 必須 | 照合用 |
| 登録番号 | 必須 | 登録完了通知メールに記載 |
| 事業者名 | 必須 | 照合用 |
| 退会理由の選択 | 必須 | 4種（A/B/C/D）から選択 |
| 退会理由の補足 | 任意 | 自由記述 |
| 開発元へのフィードバック | 任意 | 自由記述 |
| 同意チェック | 必須 | 「退会後は登録事業者としての権利を失うことを理解しました」 |

### 5.3 退会承認フロー

- たんたんが確認後に承認する。
- Claude Desktop で「**登録時のメールアドレス・登録番号・事業者名**」の3点照合を行う。
- 確認メールでの**二重確認**を行う（本人による退会意思の確認）。

### 5.4 退会処理

- 登録ステータスを「**退会済み**」に変更する。
- 公開ページから**非表示化**する。
- 退会完了通知メールを送信する。
- ライセンス上、退会後は商用利用継続の権利を失うことを通知する。退会パターンAの場合は OSS層（自社利用）として利用を継続できる旨もあわせて案内する。
- 退会後のデータの取り扱いは第6章のデータ保持ポリシーに従う。

## 第6章 データ保持ポリシー

退会後のデータ取り扱いは **案III（個人特定情報は削除）＋案Z（統計情報は匿名化保持）** を採用する。各項目の扱いは **別表3「退会後データ取扱い一覧」** に定義する。

> ※ 退会時のデータ取り扱いは、プライバシーポリシー（v2.freegroup.work/privacy/）への追記が必要（別作業・第10.2節で管理）。

### 6.1 保持方針

- 個人を特定しうる情報は**削除**する。
- 事業者の規模・利用形態・アンケート回答などの統計用情報は、**匿名化したうえで保持**する（製品改善・市場分析のため）。

### 6.2 削除項目 / 匿名化保持項目

**削除する項目（個人特定情報）**：項目1（事業者名）、項目2（所在地）、項目3（代表者氏名）、項目4（連絡先メール）、項目5（連絡先電話）、項目6（担当者氏名）、項目7（担当者メール）、項目8（インボイス番号）、項目15（ロゴ画像）、項目18（事業者ウェブサイトURL）。

**匿名化して統計用に保持する項目**：項目9（社員数区分）、項目10（上場・非上場の別）、項目11（総保有ID数の申告値・履歴含む）、項目12（商用利用トリガー区分）、項目13（利用形態の概要＝自由記述・伏字化）、項目16（業種）、項目19〜23（初回登録時アンケート）、更新時アンケート回答（毎年分）、退会理由・退会時自由記述、登録日・退会日・利用期間。

### 6.3 自由記述の伏字化

- 自由記述（項目13・退会時自由記述・アンケート自由記述等）は、Claude Desktop で固有名詞を**伏字化してから保持**する。
- 事業者名・個人名・具体的な所在地は `[事業者名]`・`[氏名]`・`[地名]` 等に置換する。
- 業種・規模・利用形態の傾向情報は保持する。
- 伏字化処理の依頼プロンプトは、退会承認時にたんたんが実行する。

### 6.4 経理データの別管理

- 請求書・入金・契約関連の経理データは、**マネーフォワードクラウド側で別管理**する。
- マネーフォワード側で法定保管期間に従って保管されるため、FG2 側で個人特定情報を保持し続ける必要はない。

### 6.5 プライバシーポリシーとの関係

- 退会時のデータ取り扱い（削除・匿名化保持・経理データの別管理）は、v2.freegroup.work/privacy/ のプライバシーポリシーに追記する必要がある（別作業）。反映状況は第10.2節で管理する。

## 第7章 書類確認・真正性担保

> ※ **本章の内容は LICENSE.md に未反映（反映待ち）。** 第10.1節で管理し、LICENSE 改訂時に正本へ反映する。本章を根拠に運用する際は、LICENSE 本文にまだ規定がない点に留意すること。

### 7.1 インボイス番号による自動照合

- 登録申請時にインボイス番号（項目8）がある場合、国税庁の「適格請求書発行事業者公表サイト」で自動照合を実施する。
- 照合内容：申告された事業者名・所在地が公表情報と一致するか。
- 実務上の照合は審査ステップ（3.4 ステップ2）で Claude Desktop が担う。

### 7.2 疑義時の追加書類請求

- 登録情報の真正性に疑義がある場合に限り、**登記簿謄本・決算書等の追加書類**の提出を求めることができる。
- 疑義がない通常の申請では、追加書類は求めない（インボイス番号＋必要時書類の方針）。

### 7.3 虚偽申告時の登録取消

- 明らかに虚偽の申告がある場合は登録を**却下**する。
- 登録後に虚偽申告が判明した場合は、登録を**取り消す**ことができる。

## 第8章 月次通知メール（将来検討）

### 8.1 通知内容案

当面は実装しない。将来の検討事項として記録する。通知内容のたたき台は次のとおり。

- 当月時点の active ユーザ数（active＝is_active=True）
