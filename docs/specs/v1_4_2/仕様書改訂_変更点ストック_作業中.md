## #1 has_minimum_info NG 時の BusinessCard 残置（方針確定・要確認事項解消）

**対象仕様書**：統合最終版

### 項目名
has_minimum_info で弾かれたケースでも BusinessCard を生成する仕様への変更（方針確定）

### 現状仕様（仕様書の該当章節）

**第15章 §15.1 cards 処理ルール一覧**（行 2497-2507）

| ID | ケース | 処理 |
|---|---|---|
| C3 | 全 card が has_minimum_info で弾かれた | status=extracted（BusinessCard 0 件）、error_message に記録 |

### 改訂内容（確定版）

C3 の処理を以下に変更する。

- has_minimum_info で弾かれた card に対しても **BusinessCard は生成する**
- ただし **Contact / Person は作らない**
- BC の `ocr_result` フィールドに `'insufficient_info'` をセット（#9 参照）
- error_message には記録しない（silent skip、コードが現実、案A方針）

詳細な §15.1 改訂内容は #10 を参照。BusinessCard モデル変更は #9 を参照。

### 改訂理由

1. **ユーザー使い勝手**：撮り直し判断の材料として「OCR が何を読み取ったのか」を確認できる
2. **OpenCV データ収集**：検出精度改善のため、has_minimum_info NG ケースの実データを蓄積する
3. **デバッグ性**：処理した事実を BusinessCard として残すことで、後追い検証が可能になる

### 影響範囲

- §15.1 ルール C3 の処理内容修正（→#10）
- §4.3 BusinessCard モデルへの ocr_result フィールド追加（→#9）
- §4.3 BusinessCard と §4.4 Contact の関係性の整理（→#11）
- §14.4 モデル固有の TextChoices に BusinessCard.OcrResult を追加（→#9）
- 別表 C に BusinessCard.OcrResult セクション追加（→#9）
- 別表 A.4 BusinessCard フィールド対照表に ocr_result 追加（→#9）
- マイグレーション必要（BusinessCard テーブルに ocr_result カラム追加）

### 確定経緯

- 2026-05-07 たんたんから方針確定の連絡（B 側サポートチャットでの提案を受けて）
- 2026-05-07 たんたんと B 側サポートクロード君で方針詳細を詰め、要確認事項3点解消
- 2026-05-07 B 側サポートクロード君から仕様書改訂担当オーパス君へ報告書受領

### 担当ブランチ

**B 側（feature/opencv-improvement）** ※初版で「A側または要確認」としていたが、B 側に確定

理由：A 側は Contact / Person / Duplicate / ActionLog 関連の作業、B 側は OCR パイプライン側の作業。BC 残置仕様変更は OCR パイプライン側の話なので B 側で実装する。

### マージタイミング

要確認のまま。ocr_result フィールド追加だけなら A 側に影響なし見込み（A 側は BC モデルを触っていない前提）が、念のため A 側マージ時に確認する。

### ステータス

ステップ1（モデル変更）実装済み。ステップ2（UI改善）も実装済み（コミット 3ceacb6）。仕様書側の記述追加のみ残っている。

### 要確認事項の解消結果

| 当初の要確認事項 | 解消結果 |
|---|---|
| Contact のない BusinessCard の判別方法 | BC 側に ocr_result フィールドを新設して区別。当初の暫定案「Contact 側からの逆引き、モデル変更なし」は不採用。理由：(1)将来拡張に強い、(2)集計クエリが書きやすい、(3)ビュー・テンプレート側の判別ロジックが分散しない、(4) v1.4.x のデータ収集（OpenCV 改善のため）に有用 |
| ユーザーへの通知文言・通知方法 | 今回のスコープでは決めない。ステップ2の UI 実装でコード君に任せる方針（たんたん判断）→ ステップ2 で #14（ocr_result_badge）として実装済み |
| ケースA／ケースB の区別方法 | is_business_card 判定で機械的に区別。ケースA → is_business_card=False → ocr_result='not_business_card'、ケースB → is_business_card=True かつ has_minimum_info NG → ocr_result='insufficient_info'、ケースB派生（card 単位の OCR 例外）→ ocr_result='ocr_failed'（将来用、ステップ2以降） |
